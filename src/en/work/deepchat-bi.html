30-sec overview

Turning “profit truth” into an interface you can decide in: moves staged, executed only after you approve.

The core user is one operator wearing three hats, so “see → understand → act” must fold into a single flow. I defined the four-stage HITL chain, stepped Chat back to an attribution-and-explanation layer and made the board the main surface for action decisions, audited the live product into 8 interface problems, and put the design capital into “trust + executability”.

01 Context

Operators aren’t short on data — they’re short on profit truth and the next move

Platform ROAS (return on ad spend) looks healthy; subtract COGS (cost of goods sold), platform fees, shipping and refunds — and that “winning” campaign is quietly burning cash. The real gap is a tooling split: finance tools stop at the report, attribution tools stop at insight, and “seeing” and “acting” live in two different tabs; insight ends in save / export / share, not in execution.

03 Stage 3 · Designing for AI Agents · 2026.03 – 07

Intelligence ready, trust and execution not: 8 interface problems

I audited the live product and found 8 interface problems. There is only one P0: the “see it, act on it” loop is broken — the agent delivers ready-to-go actions, but there is no “review before execute” gate, and no way to execute in place. The other seven: buried reasoning, model-speak, empty / broken data shown raw, actions mixed with evidence, no single decision surface, drill-down by double-click, no single next step.

The scarcest resource isn’t more analysis — it’s trust + executability. All design capital went to P0 / P1: make high-risk actions safe first, then make reasoning visible and translate analysis into “profit”.

Four design decisions: understand it, trust it, dare to hand budget moves to the agent

04 Stage 2 · Designing AI Products · 2025.12 – 2026.03

Chat stops at insight — the board owns decisions

User feedback from competitor research: actionable insight from Chat alone or a dashboard alone — both paths are inefficient. So the roles were redefined: the board leads action decisions, Chat plays the supporting role of attribution and explanation; a multi-turn conversational query path lets answers drill back into the board — asking is deciding.

Two layers of evidence hold up this architectural call: internal testers spoke first (“It’s slow.” “I never asked for all this.”), and 7 competitors point to the same conclusion — chat-first products treat insight as the end point, and the category leader’s fix was to add a separate, human-approved action queue beside the chat. That set Chat’s scope discipline: Explain → (only when asked) Diagnose → (only when invited) Act.

Three options, compared for real

Option A · Chat as the protagonist: commands and queries all happen in the chatroom — the least effort per decision, at the cost of a black box. Option B · conclusion reports on the board: less action-oriented information, more trend judgment. Option C · action-oriented Cockpit: the board presents the conclusions, and Cockpit steps back to an evidence layer. All three were built as interactive HTML prototypes (v6 design system) and compared for real.

05 Stage 1 · Building SaaS order · 2025.10 – 12

Turning an engineering-built product into a standard SaaS people can read and use

Engineering’s build was hard to read and use; order was needed at the IA and logic level. I rebuilt the information hierarchy and translated complex business data into visualization, surfacing what users care about most day to day — non-technical users read fast and act. Before (2025.10, the engineers’ version): a Chat home with raw table names → a list of dashboards → hand-written SQL to get numbers → cockpit overview; After (2026.02, the shipped version): boards organized by role and task.

07 Retrospective

What I design changed: from screens to the rules and environment that let an agent work safely

The product isn’t short on intelligence — it’s short on an interface people dare to use: legible (visible reasoning), credible (evidence + profit), safe to act. The lever isn’t more charts; it’s these three things. Insight → Direction → Goal → Strategy → Solution — the order I judge in, and this page’s skeleton.
